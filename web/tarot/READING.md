# ห้องไพ่ 3 ใบ — ต้นแบบ 2026-10-16

เปิด `http://127.0.0.1:3010/reading/` หรือกด **เปิดไพ่ 3 ใบ →** จากหน้าแรก

## ขอบเขตปัจจุบัน

Next.js static export; สถานะอยู่ใน React memory ของหน้านี้ รีเฟรชหรือออกหน้าเริ่มใหม่ ไม่เก็บคำถามใน localStorage, URL, logs หรือ backend ไม่มี AI API, บัญชี, ประวัติ, analytics หรือการชำระเงิน ต้นแบบใช้ไพ่ตั้งตรงเท่านั้น

หมวดความรักมี 6 สถานะและความหมายรายใบจากแชทที่เจ้าของเลือก ยังไม่ได้ผ่านการรับรองจากเจ้าของ การเรียงอดีต/ปัจจุบัน/อนาคตและบทสรุปเป็นข้อความประกอบการทดลอง ไม่ใช่กฎการอ่านไพ่ร่วมกัน หมวดงาน เงิน และภาพรวมชีวิตแสดงสถานะรอความรู้ชัดเจน ช่องคำถามอิสระแสดงบริบท แต่ไม่วิเคราะห์ความหมายของข้อความ

สำรับ 78 รหัสคงเดิมจาก `source/cards-78.json`; `lib/reading-cards.json` มีเฉพาะข้อมูลที่ใช้แสดงและที่มา ภาพ 5 ใบตาม public/cards เดิม อีก 73 ใช้ชื่อกับกรอบภาพอยู่ระหว่างจัดทำ ภาพที่โหลดผิดพลาดใช้กรอบสำรองเช่นกัน ไม่ใช้ภาพไพ่ใบอื่นทดแทน

## Flow และ invariants

`topic → question → shuffling → gathering → spreading → selecting → revealing → locked → reading`

- Fisher–Yates ใช้ Web Crypto + rejection sampling สุ่มครบหนึ่งสำรับต่อรอบ ไม่ใช้ sort(random) และไม่สุ่มใหม่ตอนแตะเลือกหรือปลดล็อก
- `STOP` หยุด GSAP timeline โดยคง pose ล่าสุด จากนั้น tween กลับเป็นกอง ก่อนแสดงพัดไพ่ ไม่ seek กลับเฟรมแรก
- สำรับเป็น 78 ปุ่มตามลำดับเดิม มุมมองพัดเลื่อนแนวนอน/กริดใช้รหัสเดียวกัน ใบที่เลือกซ่อนจากสำรับและคืนได้ก่อนเปิด ไม่มีการอ่านชื่อไพ่ผ่าน accessible label ก่อนเปิด
- แตะไพ่เพื่อยก แล้วกดยืนยัน; pointer movement/scroll เกิน 9px ไม่ถือเป็น tap ยืนยัน ใช้ ArrowLeft/Right และ Home/End เลื่อนไปหาไพ่ด้วยคีย์บอร์ดได้
- เลือกได้สามใบต่างกัน ยกเลิกใบกลางแล้วไพ่ถัดไปเลื่อนช่องซ้าย บทบาทตำแหน่งผูกกับลำดับปัจจุบันที่ผู้ใช้เห็น
- เปิดเรียงทีละใบแล้วคงสำรับ/ผลเดิมเมื่อปลดล็อก ปุ่มปลดล็อกเป็น demo ไม่มี entitlement หรือ price
- Reduced motion หยุดการหมุน/บิน/พลิก แต่ยังรอผู้ใช้กดหยุดสับและเลือกเอง หากโหลด GSAP ไม่สำเร็จใช้สำรับนิ่งและยังเดิน flow ต่อได้
- ใช้ CSS/GSAP local asset เดิม ไม่สร้างภาพใหม่ ไม่ใช้เครดิตหรือส่งข้อมูลให้บริการภายนอก

## ข้อตกลงข้อมูล

Types และ pure functions อยู่ใน `lib/reading.ts`:

- `ReadingRequest`: category, situation, question, spread='past-present-future'
- `DrawSession`: phase, deck (78 IDs), selected (ordered IDs สูงสุด 3), revealed (0–3), unlocked
- `ReadingResult`: request, entries (card ID/name/position/text/source), summary, reflection, status='demo', knowledgeVersion
- `createReading()` ตรวจครบ 3 ใบไม่ซ้ำและสถานการณ์ตรงหมวด ไม่รับกรณีที่ไม่มีข้อมูลมาแทนคำอ่านจริง
- `sessionReducer()` กัน stale transition, rapid duplicate, early reveal/unlock, และการเปลี่ยนสำรับระหว่างเลือก

## Second Brain: จุดต่อระยะถัดไป

เก็บเป็นข้อมูล owner-reviewed แยกจากหน้าจอ 4 ชั้น: ความหมายรายใบตามบริบท/ตำแหน่ง, กฎไพ่ประกอบ, กรณีศึกษาที่ลบข้อมูลระบุตัวบุคคล, และสำนวนเจ้าของ การเปลี่ยนแต่ละครั้งมี source reference, review status และ knowledge version

วงจร: เพิ่มหรือแก้ → เจ้าของตรวจทาน → อนุมัติ → เผยแพร่รุ่นความรู้ ไม่รับเรื่องลูกค้าเข้าคลังอัตโนมัติ ข้อมูลส่วนบุคคลอยู่ในเครื่องตาม CLAUDE.md; ชุดกรณีทดสอบใช้เรื่องสมมติ ไม่มีข้อมูลจริงจากลูกค้า

ตัวสร้างคำอ่านรุ่นจริงต้องรับทั้ง request และไพ่ตามตำแหน่งทั้งสาม ดึงความหมายกับกรณีที่เกี่ยวข้อง ประเมินกฎประกอบ แล้วสังเคราะห์คำอ่านพร้อมแหล่งที่มา ไม่ใช้ค่าเฉลี่ยดี–ร้ายแทนบริบท ถ้าความรู้ไม่พอให้ระบุว่ารอข้อมูล ไม่แต่งกฎเป็นคำอ่านเจ้าของ การ fine-tune ไม่ใช่ขอบเขตรอบนี้

การเพิ่มภาพ: วางไฟล์ภาพที่ผ่านตรวจใน public/cards แล้วกำหนด art URL ของ card ID ให้ตรง ห้ามเปลี่ยนชื่อหรือรหัสไพ่เพื่อให้ตรงชื่อไฟล์ที่ผิด; เพิ่ม QA ว่า ID/ภาพ/คำอ่านตรงกัน

## ก่อนเปิดบริการเก็บเงินจริง

Static export นี้ไม่ป้องกันข้อมูลคำอ่าน การเก็บเงินจริงต้องมี backend สร้าง session ของสำรับที่เชื่อถือได้ บันทึกผลเลือกครั้งเดียว ตรวจการชำระเงิน/สิทธิ์บน server และส่งคำอ่านฉบับเต็มเฉพาะผู้มีสิทธิ์ ต้องไม่ส่งคำตอบที่ขายจริงลง public JSON หรือ HTML ก่อนตรวจสิทธิ์ การกลับจากหน้าชำระเงินยังใช้ไพ่ชุดเดิม และ retry ต้องไม่สร้างรายการจ่ายซ้ำ

ยังไม่เลือกราคา ผู้ให้บริการรับชำระ ฐานข้อมูล หรือ AI provider การเพิ่มบริการเหล่านี้เป็นงานระยะถัดไปหลังตรวจ UI และคำอ่าน
